# Case: Student Task Management System

## Business Context
A campus needs a single application through which lecturers, students, and administrators can manage coursework tasks. Current process details are intentionally limited; missing facts must be elicited rather than invented.

## Initial Problem
Assignment creation, submission, grading, deadline monitoring, and academic administration need a consistent workflow and reliable records. Stakeholders need visibility into task status while access and data changes remain controlled.

## Initial Objectives
- Allow lecturers to publish assignments with deadlines and assess submissions.
- Allow students to find, submit, and track their assignments.
- Allow administrators to maintain users, courses, and system configuration.
- Preserve usability, security, performance, reliability, and data integrity.

## Known Stakeholders
- Lecturer
- Student
- Administrator

## Known Scope
Assignment creation, task viewing, file submission, grading, feedback, deadlines, status monitoring, user management, course management, configuration, and reporting.

## Information Boundaries
The case provides no approved values for budget, project schedule, file types, file-size limits, retention, notification channels, authentication integration, grading scale, performance load, or availability target. These are not facts until confirmed.
